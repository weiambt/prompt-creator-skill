# Prompt Creator Skill

一个用于快速生成高质量、结构化提示词（Prompt）的 Claude Code Skill。当用户提出提示词创建需求时，Skill 自动分析需求完整性，通过追问补全关键信息，动态选择合适的框架要素组合，最终生成 N 个不同版本的定制化提示词供用户选择使用。

> **中文版本** | [English Version](./README.md)

---

## Prompt核心框架

内置 6 种提示词框架，作为动态合成的要素来源。框架是静态的，但合成是动态的——根据场景自由组合要素。

---

### 1. RTF — Role + Task + Format

**结构：**

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│  Role   │ ──▶ │  Task   │ ──▶ │ Format  │
│  角色    │     │  任务   │     │  格式   │
└─────────┘     └─────────┘     └─────────┘
```

**要素说明：**

| 要素 | 含义 |
|------|------|
| Role | 定义 AI 扮演的身份或专业背景 |
| Task | 具体要完成的目标或任务 |
| Format | 输出的格式、风格或语气要求 |

**总结：** 三要素直线串联，最简洁的框架。

**适合场景：** 通用任务、简单任务、快速一次性需求。

---

### 2. ICIO — Instruction + Context + Input + Output

**结构：**
```
┌────────────┐   ┌──────────┐   ┌────────┐   ┌────────┐
│Instruction │──▶│ Context  │──▶│ Input  │──▶│ Output │
│   指令      │   │  上下文  │   │  输入  │   │  输出  │
└────────────┘   └──────────┘   └────────┘   └────────┘
```

**要素说明：**
| 要素 | 含义 |
|------|------|
| Instruction | 核心任务指令 |
| Context | 背景信息与辅助上下文 |
| Input | 需要处理的文本或数据 |
| Output | 结果的格式或表达要求 |

**总结：** 四要素线性流程，上下文贯穿始终，适合多阶段推理。

**适合场景：** 需要上下文理解的任务、带背景信息的分析、内容创作。

---

### 3. CRISPE — Capacity + Role + Insight + Statement + Personality + Experiment

**结构：**
```
┌──────────┐  ┌────────┐  ┌────────┐  ┌─────────┐  ┌───────────┐  ┌───────────┐
│ Capacity │─▶│  Role  │─▶│ Insight│─▶│Statement│─▶│Personality│─▶│Experiment│
│  能力边界 │  │  角色  │  │  洞察  │  │  任务声明 │  │   个性    │  │   探索   │
└──────────┘  └────────┘  └────────┘  └─────────┘  └───────────┘  └───────────┘
```

**要素说明：**
| 要素 | 含义 |
|------|------|
| Capacity | AI 的能力边界定义 |
| Role | 身份定位 |
| Insight | 知识视角或洞察点 |
| Statement | 具体任务目标 |
| Personality | 个性化语气与风格 |
| Experiment | 探索性要求（假设、多答案等）|

**总结：** 六要素串联，强调"人格化"与"可探索性"，适合深度创作。

**适合场景：** 学术/科研、内容创作、深度分析报告、创意写作。

---

### 4. CO-STAR — Context + Objective + Scope + Tone + Audience + Response

**结构：**
```
         ┌─────────┐
         │ Context │
         │  上下文  │
         └────┬────┘
              │
              ▼
┌────────┐  ┌──────────┐  ┌────────┐
│ Scope  │─▶│ Objective│─▶│  Tone  │
│  范围  │  │   目标   │  │  语气  │
└────────┘  └──────────┘  └───┬────┘
                             │
                             ▼
                    ┌──────────┐  ┌──────────┐
                    │ Audience │─▶│ Response │
                    │   受众   │  │   响应   │
                    └──────────┘  └──────────┘
```

**要素说明：**
| 要素 | 含义 |
|------|------|
| Context | 任务相关的场景与背景 |
| Objective | 明确要达成的结果或目的 |
| Scope | 任务边界、限制条件 |
| Tone | 输出风格（正式/幽默/专业/轻松）|
| Audience | 目标读者或接收对象 |
| Response | 输出的格式或结构要求 |

**总结：** 六要素网状结构，Context 作为基础串联其余，强调风格与受众。

**适合场景：** 复杂结构化输出任务、营销内容、青少年教育。

---

### 5. TIDD-EC — Task + Instructions + Do + Don't + Example + Content

**结构：**
```
┌────────┐   ┌────────────┐   ┌─────┐   ┌────────┐
│  Task  │──▶│ Instructions│──▶│ Do  │   │Don't   │
│  任务  │   │    指令     │   │  做  │──▶│  禁止  │
└────────┘   └────────────┘   └─────┘   └────────┘
                  │                              │
                  ▼                              │
             ┌─────────┐                         │
             │ Example │◀────────────────────────┘
             │  示例   │
             └────┬────┘
                  │
                  ▼
            ┌──────────┐
            │ Content  │
            │  用户内容 │
            └──────────┘
```

**要素说明：**
| 要素 | 含义 |
|------|------|
| Task | 任务性质和目标 |
| Instructions | 执行任务的具体步骤 |
| Do | 应该执行的操作 |
| Don't | 应该避免的错误 |
| Example | 期望输出的示例 |
| Content | 用户提供的背景信息 |

**总结：** 指令 + 边界双向约束，Example 提供参照，适合需要明确指导边界的任务。

**适合场景：** 教育培训、法律咨询、技术支持、规范性内容生成。

---

### 6. BROKE — Background + Role + Objective + Key Result + Evolution

**结构：**
```
┌───────────┐  ┌────────┐  ┌──────────┐  ┌────────────┐  ┌─────────┐
│ Background│─▶│  Role  │─▶│ Objective│─▶│ Key Result │─▶│Evolution│
│   背景    │  │  角色   │  │   目标   │  │   关键结果  │  │  进化   │
└───────────┘  └────────┘  └──────────┘  └────────────┘  └─────────┘
     │                                                   ▲
     └───────────────────────────────────────────────────┘
                        反馈循环
```

**要素说明：**
| 要素 | 含义 |
|------|------|
| Background | 背景信息或上下文 |
| Role | 模型应扮演的角色 |
| Objective | 具体目标或预期结果 |
| Key Result | 衡量成功的标准或指标 |
| Evolution | 改进建议或后续步骤 |

**总结：** 五要素线性 + 反馈循环，目标导向、可迭代优化。

**适合场景：** 活动策划、产品设计、目标导向型任务、需要持续改进的项目。

| 框架 | 要素数 | 核心特征 | 复杂度 |
|------|--------|----------|--------|
| RTF | 3 | 简洁直接 | ⭐ |
| ICIO | 4 | 线性流程 | ⭐⭐ |

| CRISPE | 6 | 人格化探索 | ⭐⭐⭐ |
| TIDD-EC | 6 | 边界约束 | ⭐⭐⭐ |

**动态合成示例：**
- 简单翻译任务 → RTF（Role + Task + Format）
- 带上下文的分析报告 → ICIO + CO-STAR（补充 Tone + Audience）
- 需要边界的教育培训内容 → TIDD-EC（补充 Do/Don't）
- 目标导向的活动策划 → BROKE + CO-STAR（补充 Tone）

## 设计原则

### 核心理念：框架是参考，不是枷锁

现有提示词框架（RTF、ICIO、CRISPE、CO-STAR、TIDD-EC、BROKE）都是静态的模板，它们是工具，不是教条。真正的力量在于**根据场景动态组合要素**。

**反面教材：**

> "我需要用 CO-STAR 框架写一个 prompt，因为它是最好的框架。"

这是本末倒置。框架的价值在于其**核心要素**，而非框架名称本身。

**正确姿势：**

> "我需要让 AI 扮演资深技术面试官，考察候选人的系统设计能力，输出结构化的面试评估表，语气要专业但不失亲和力。"

然后从多个框架中提取所需要素：

- **角色**（RTF/CRISPE）→ "资深技术面试官"
- **上下文+目标**（ICIO/CO-STAR）→ 系统设计能力考察
- **输出格式**（RTF/CO-STAR）→ 结构化面试评估表
- **语气**（CO-STAR/CRISPE）→ 专业但不失亲和力

最终合成的架构可能无法归属于任何一个单一框架，但它**最贴合当前场景**。

---

### 三大设计原则

| 原则 | 说明 |
|------|------|
| **场景优先** | 先理解需求，再选择框架。框架为需求服务，不是需求为框架服务。 |
| **要素组合** | 从不同框架中提取最相关的要素，像搭积木一样动态组合。 |
| **透明交付** | 每个 prompt 都附带框架来源说明，让用户理解为什么这样设计。 |

---

### 设计原则在实践中的体现

| 实践 | 说明 |
|------|------|
| **追问策略** | 信息不足时，先补全关键要素，而不是强行套框架。 |
| **多样性保障** | 生成多个版本时，使用不同的框架要素组合，避免同质化。 |
| **拒绝死板** | 不存在"必须用哪个框架"的说法，每个 prompt 都是定制化产物。 |
| **用户可理解** | 输出时标注框架来源，让用户学习框架要素，而非死记框架名称。 |



## 功能

| 功能             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **需求分析**     | 自动从用户描述中提取任务类型、目标受众、输出格式、风格语气等关键要素 |
| **智能追问**     | 缺失关键信息时，每次只问 1 个问题，最多 3 个                 |
| **动态框架合成** | 根据场景从 6 种框架中选取相关要素，组合成最适合的架构        |
| **多版本生成**   | 生成 N 个不同版本的 prompt，保证框架多样性和措辞差异         |
| **框架标注**     | 每个 prompt 都附带框架参考来源说明                           |



## 优点

| 优点           | 说明                                  |
| -------------- | ------------------------------------- |
| **多框架融合** | 内置 6 种提示词框架，可自由组合要素   |
| **多版本输出** | 一次生成 N 个不同版本，便于对比选择   |
| **智能追问**   | 信息不足时逐个追问关键问题，最多 3 个 |
| **即取即用**   | 输出的 prompt 可直接复制使用          |
| **可配置**     | 生成数量、追问上限均可自定义          |
| **零学习成本** | 只需描述需求，Skill 自动处理其余      |



## 安装

将 skill 文件夹放入 Claude Code 的 skills 目录：

```bash
# 克隆或复制 skill 到对应目录
cp -r prompt-creator-skill ~/.claude/skills/prompt-creator-skill
```

可选：创建配置文件 `~/.prompt-creator/config.json`：

```json
{
  "defaultPromptCount": 3,
  "maxQuestions": 3
}
```

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `defaultPromptCount` | 3 | 正常模式下默认生成的 prompt 数量 |
| `maxQuestions` | 3 | 需求信息不足时，最多追问的问题数 |

---

## 交互流程

```
用户描述需求
    ↓
Skill 分析需求完整性
    ↓ [信息不足]
追问 1-3 个问题（每次只问 1 个）
    ↓ [信息完整]
动态框架合成 + 生成 N 个不同版本 prompt
    ↓
直接输出给用户
```

## Demo 示例

### 1. 简单需求 — 缺少关键信息

**用户输入：**
> 帮我写一个翻译的 prompt

**Skill 追问：**
> 请问目标受众是谁？（例如：商务人士、学生、内容创作者）

---

### 2. 完整需求

**用户输入：**
> 写一个将英文文章摘要成中文的 prompt，目标受众是学术研究人员，输出用简洁的段落形式，语气专业正式

**Skill 输出：**
```
=== Prompt 1/3 ===
[prompt 正文]

> 框架参考: RTF (角色+任务+格式) + CRISPE (Personality)
> 适用场景: 学术英文文章的快速摘要

===

=== Prompt 2/3 ===
[prompt 正文]

> 框架参考: ICIO (Instruction+Context+Output)
> 适用场景: 需要保留关键术语的学术摘要

===

=== Prompt 3/3 ===
[prompt 正文]

> 框架参考: CO-STAR (Context+Objective+Tone+Audience+Response)
> 适用场景: 结构化长文摘要
```

---

### 3. 复杂需求 — 活动策划

**用户输入：**
> 帮我策划一个公司年度晚会的 prompt，要求有明确目标和可衡量的结果

**Skill 输出：**
```
=== Prompt 1/3 ===
[prompt 正文]

> 框架参考: BROKE (背景+角色+目标+关键结果+进化)
> 适用场景: 目标导向的年度晚会策划

> 框架参考: BROKE + TIDD-EC (补充Do/Dont边界)
```

## 约束与边界

### MVP 范围内
- 纯生成，不含评测
- 单次对话内完成所有生成
- 支持简体中文交互

### MVP 范围外（未来版本）
- 评测模式（多轮迭代 + 评测报告）
- 多轮对话式 Prompt 优化
- Prompt 性能追踪
- 英文等其他语言支持
- Prompt 持久化存储与管理
