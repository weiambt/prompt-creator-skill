# Prompt Frameworks Reference

本文件包含 6 种内置提示词框架的完整定义，作为动态合成的要素来源。

## 框架列表

| 框架 | 核心要素 | 适用场景 |
|------|----------|----------|
| RTF | Role + Task + Format | 通用任务、简单任务 |
| ICIO | Instruction + Context + Input + Output | 需要上下文理解、多阶段推理 |
| CRISPE | Capacity + Role + Insight + Statement + Personality + Experiment | 学术/科研、内容创作 |
| CO-STAR | Context + Objective + Scope + Tone + Audience + Response | 复杂结构化输出任务 |
| TIDD-EC | Task + Instructions + Do + Don't + Example + Content | 需要明确边界的任务 |
| BROKE | Background + Role + Objective + Key Result + Evolution | 目标导向、持续改进型任务 |

---

## 1. RTF（Role–Task–Format）

简洁高效，适合通用类任务或简单任务。

**核心要素：**
- **Role**：定义模型的身份或专业背景
- **Task**：说明模型要完成的具体目标
- **Format**：指定输出的格式、风格或语气

**示例：**
```
# Role
你是一名资深市场分析师。

# Task
请分析当前中国新能源汽车市场的发展趋势，指出未来三年的主要增长点。

# Format
请以 Markdown 表格形式输出，包含"趋势"、"原因"、"预测增长率"三列。
```

---

## 2. ICIO（Instruction–Context–Input–Output）

强调通过清晰分隔任务指令、背景信息、输入与输出要求，使模型在复杂场景中仍能高效执行。

**核心要素：**
- **Instruction**：核心任务说明
- **Context**：背景与辅助信息
- **Input**：具体需要处理的文本或数据
- **Output**：结果格式或表达要求

**示例：**
```
# Instruction
请为指定产品生成一段简短、有吸引力的营销文案。

# Context
你是一名资深品牌营销文案策划，擅长为电商产品撰写高转化率的广告语。目标受众是年轻、注重品质的都市白领。

# Input
产品名称：AI健康监测手环
产品特点：实时监测、可测量血压血氧、监测睡眠和呼吸暂停、外观时尚简约、佩戴轻盈舒适

# Output
请输出一段不超过100字的营销文案，语言简洁、有节奏感，突出健康的生活方式。
```

## 3. CRISPE（Capacity–Role–Insight–Statement–Personality–Experiment）

让提示词更"人格化"与"可控化"，常用于学术、科研、内容创作等领域。

**核心要素：**
- **Capacity**：确定智能体的能力边界
- **Role**：明确身份定位
- **Insight**：提供必要的知识视角或洞察点（上下文背景）
- **Statement**：定义具体的任务目标
- **Personality**：设置个性化的语气与风格
- **Experiment**：指定探索性要求（如假设、生成多个答案等）

**示例：**
```
# Capacity and Role
你是一名资深市场策略分析师，擅长品牌定位与消费趋势洞察，熟悉零售行业的数据分析与竞争对比方法。

# Insight
某科技品牌计划在明年推出一款主打AI功能的智能手表，目标群体为25-40岁的城市白领。公司希望通过差异化策略抢占高端可穿戴设备市场。

# Statement
请撰写一份市场策略分析报告，包含：
1. 当前智能手表市场格局与主要竞争者分析
2. 目标用户画像与购买动机
3. 产品差异化与品牌定位建议
4. 三条可执行的市场推广策略

# Personality
请以专业咨询顾问的语气撰写，逻辑清晰、数据导向。报告语言应简洁有力，避免空泛表达。

# Experiment
在报告结尾，请额外提供一个"创新性市场假设"，例如：基于AI健康数据洞察的"主动健康推荐"功能，并简要说明这一创新可能带来的商业价值与潜在风险。
```

## 4. CO-STAR（Context–Objective–Style–Tone–Audience–Response）

通过明确任务要素，帮助精准传递需求，适用于复杂或中等复杂度的场景。

**核心要素：**
- **Context**：提供任务相关的场景、前提或背景信息
- **Objective**：明确希望达成的具体结果或目的
- **Scope**：界定任务的边界，包括内容涵盖范围、限制条件
- **Tone**：指定输出内容的风格（正式、幽默、专业、轻松等）
- **Audience**：说明内容的目标读者或接收对象
- **Response**：要求输出的格式、结构或呈现方式

**示例：**
```
# Context
近年来青少年沉迷社交媒体、遭遇网络不良信息的问题频发，学校计划开展相关主题教育活动；

# Objective
帮助青少年理解合理使用社交媒体的重要性，并提供可操作的建议；

# Scope
聚焦 13-17 岁青少年，涵盖使用时长管理、信息辨别、隐私保护 3 个核心方面，避免过于学术化的理论；

# Tone
亲切、鼓励，像学长学姐的建议，避免说教；

# Audience
初中至高中阶段的学生；

# Response
分点列出 5 条具体建议，每条配一个简短案例或比喻。
```

## 5. TIDD-EC（Task–Instructions–Do–Don't–Example–Content）

通过清晰的**任务分解和操作规范**，帮助模型生成更精准、可靠和可控的输出。适用于需要明确指导边界的任务。

**核心要素：**
- **Task**：明确任务的性质和目标
- **Instructions**：提供执行任务的具体步骤或指导
- **Do**：列出应当执行的具体操作或行为
- **Don't**：指出应避免的错误或不当行为
- **Example**：提供期望输出的示例
- **Content**：用户提供的背景信息或数据

**示例：**
```
# 任务
撰写法律意见书

# 指令
根据客户提供的案件信息，分析法律风险并提出可行建议

# 你应该做
- 结合相关法律法规进行分析
- 条理清晰地列出风险点
- 提供操作性建议

# 你禁止做
- 不要提供具体的法律诉讼策略或个案判决
- 避免主观推测，确保内容专业客观

# 示例
客户希望了解合同条款中的潜在风险，分析指出关键条款可能存在的履约争议，并给出建议如完善合同条款或加强证据准备

# 用户内容
- 案件类型：商业合同纠纷
- 关键条款：付款条款、违约责任、交付时间
```

## 6. BROKE（Background–Role–Objective–Key Result–Evolution）

引导生成更贴合目标、可评估和可迭代优化的输出。适用于活动策划、产品设计、内容创作等领域。

**核心要素：**
- **Background**：描述任务的背景信息或上下文
- **Role**：明确模型在任务中应扮演的角色或身份
- **Objective**：定义任务的具体目标或预期结果
- **Key Result**：设定衡量任务成功的标准或指标
- **Evolution**：提供改进建议或后续步骤

**示例：**
```
# 背景
学校希望提高学生的环保意识，计划开展一次以校园环保为主题的活动。

# 角色
作为校园活动策划师，负责设计活动方案并确保可执行性。

# 目标
通过活动让学生了解环保知识并积极参与实践。

# 关键结果
活动结束后，学生参与率达到80%以上，提交的环保创意作品数量不少于50份。

# 进化
根据活动反馈调整宣传策略和活动形式，优化互动环节，使下一次活动更具吸引力。
```

---

## 使用指引

动态合成时，根据用户需求的场景类型，从上述框架中选取相关要素组合使用。

**合成示例：**
- 简单翻译任务 → RTF（Role + Task + Format）
- 带上下文的分析报告 → ICIO + CO-STAR（补充 Tone + Audience）
- 需要边界的教育培训内容 → TIDD-EC（补充 Do/Don't）
- 目标导向的活动策划 → BROKE + CO-STAR（补充 Tone）

最终输出是"杂交"产物，不拘泥于单一框架。
